# Doerr P1 reuse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use code-run-plan to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the four P1 extractions from the Doerr review: a standalone inline edit, record picking on the existing combobox and tag input, a property-row layout, and a keyboard tree with inside-drop intent.

**Architecture:** Two new component families (`inline-edit`, `property-list`, `tree`) plus non-breaking extensions of Combobox, Tag input and Drag drop. Application state, persistence and folder invariants stay with the consumer. Inline edit's commit and cancel rules are one shared helper that Table edit already follows, so a rename and a cell edit cannot drift.

**Tech Stack:** TypeScript, React (optional peer), light-DOM custom elements, CSS tokens, Node tests, Playwright.

**Spec:** `plans/2026-10-doerr-reuse.md` (P1 rows only: inline edit, record picker, property list, tree).

## Global Constraints

- Ayywi's product is a token-driven CSS class contract with framework-free behavior, thin React wrappers and light-DOM elements where interaction needs them. Moving a Doerr React file alone does not finish an extraction.
- Remove `useStore`, application actions, `Task`/`Database`/`Folder` assumptions and Tauri imports. Use controlled values, slots, neutral IDs and intent callbacks. Keep persistence, validation of business rules and undo history in consumers.
- Preserve RTL and density behavior. Verify focus, keyboard operation, IME input, long labels, empty/loading/error/disabled states, theme contrast and forced colours before promoting borrowed behavior. Existing Doerr code is source material, not proof of a complete portable accessibility contract.
- Reuse existing internals before creating another family. Especially share `TableEdit` draft/commit behavior, Combobox navigation, floating placement and Drag drop. Let the app decide how dates, records and queries are interpreted.
- Publish metadata, HTML and React examples with the feature so Ayywi's generated docs, manifest and AI tooling can recommend it. Follow the repository's component checklist and required checks during implementation.
- Tokens only in component CSS (`var(--ayy-…)`). Tints via `color-mix()` with a token. No hex, rgb or hsl.
- Logical properties only. No `left`/`right`, `margin-left`, `text-align: left`, and no `:dir()`.
- State from native or ARIA attributes, never a JS-only class. `ayy-` prefix on every class and keyframe. `--ayy-` on every public custom property; private ones are `--_x`. New public hooks go in `PUBLIC_HOOKS` in `scripts/lib/contract.mjs`.
- Visible `:focus-visible` ring on every interactive part: `outline: 2px solid var(--ayy-color-ring); outline-offset: 2px;`. Colour-only state needs `@media (forced-colors: active)`.
- Zero runtime dependencies. Never edit generated files (`src/css/tokens.css`, `src/tokens.ts`, `manifest/`, `llms*.txt`, `llms/`, `ai/AGENTS.snippet.md`, `ai/cursor/ayywi.mdc`, `ai/skills/ayywi/reference.md`). Edit the source and run `pnpm generate`.
- `*.meta.json` `states` lists every key in `STATES` (`scripts/lib/contract.mjs`), in that order: `default`, `hover`, `pressed`, `focus`, `disabled`, `selected`, `error`, `loading`. `classes` lists every class the CSS defines and nothing else. `category` is one of Actions, Navigation, Forms, Layout, Overlays, Feedback, Data display.
- Changelog entries go under `## Unreleased`, title on row 1, description indented on row 2. Link a component as `**[Name](#/slug)**`.
- README line 11 counts components ("all 74 components"). `pnpm check` fails when that count or the Components table is stale. Bump the count only when this task adds a component folder.
- Icons are Hugeicons via `<Icon>` in `.tsx` and `iconSvg()` markup in `.html`. Write the `.tsx` example first and render it to HTML (react-dom/server) so the two match. Custom-element wrappers and comments may differ.
- JSON under `src/components/` and `tokens/` is hand-formatted (short objects on one line). Do not rewrite a file with `JSON.stringify`.
- The working tree may already contain unrelated uncommitted work from before this plan. Never `git add -A`, `git add .` or `git commit -a`. Stage only files this task created or edited. Do not stage a file that was already dirty unless every hunk in it is yours.
- Do not release: no version bump, no rename of `## Unreleased`, no tag, no publish.
- There is no hosted CI. Never add GitHub Actions or other `.github/` automation.

## Review Focus

- IME composition: Enter during `isComposing` (or `keyCode === 229`) must not commit an inline edit or create a record. A person finishing a composed character expects the character, not a save.
- Formatted display versus raw value: blurring a price field must show the formatted string again, and focusing it must show the raw digits. Committing must report the raw value, not the formatted one.
- A create row must not appear for a query that already matches a label ignoring case, and activating it must not also select an option.
- A tree arrow move must skip children of a collapsed node and skip disabled nodes. Dropping a node inside itself, or into a node the `accepts` callback refuses, must not move it.
- Existing Combobox, Tag input, Table edit and sortable drag behavior must stay the same when the new props are absent. A single-value combobox and a string tag field are not broken by the record-picker additions.

- Produces:

```ts
export type DropIntent = "before" | "after" | "inside";

/** Top quarter before, bottom quarter after, middle inside. size <= 0 returns "before". */
export function dropIntentAt(offset: number, size: number): DropIntent;

export interface TreeFlatItem {
  id: string;
  parentId: string | null;
  label: string;
  expanded: boolean;
  hasChildren: boolean;
  disabled: boolean;
}

export type TreeKey = "ArrowDown" | "ArrowUp" | "ArrowRight" | "ArrowLeft" | "Home" | "End" | "F2";

export function treeMove(
  items: TreeFlatItem[],
  activeId: string,
  key: TreeKey,
): { activeId: string; expanded?: boolean; rename?: boolean };

export function treeTypeahead(items: TreeFlatItem[], activeId: string, char: string): string;
```

`items` is document order, including children of collapsed nodes. `treeMove` and `treeTypeahead` skip a node whose ancestor is collapsed, and skip `disabled` nodes. ArrowDown/Up move to the next or previous visible enabled node, wrapping not required (stop at the ends). ArrowRight on a collapsed parent sets `expanded: true` and keeps `activeId`. ArrowRight on an expanded parent moves to its first visible enabled child. ArrowLeft on an expanded parent sets `expanded: false`. ArrowLeft on a collapsed node or a leaf moves to its parent. Home/End move to the first or last visible enabled node. F2 on an enabled node returns `{ activeId, rename: true }` and does not change expansion. A disabled active id moves as if nothing is active (first visible enabled node for ArrowDown and Home).

`treeTypeahead` returns the next visible enabled node whose label starts with `char`, case-insensitive, wrapping, or `activeId` when `char` is not a single letter or nothing matches.

Drag drop: add optional `nest?: boolean` to `DragDropOptions` (default false). When false, hit testing stays the 50% before/after split and `DragMove` gains no required field. Keyboard reparent is out of scope. Inside intent is pointer-only. Say that in the drag-drop meta.
